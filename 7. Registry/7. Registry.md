Think of a **private registry as your own private Docker Hub**.

First, forget the commands. Understand **why we need it**.

### 1. Normal Docker workflow

You have an image on your machine:

```text
Your laptop
   |
   └── myapp:1.0
```

If you want another server to use this image, you need somewhere to **store the image and let that server download it**.

Docker Hub can do this:

```text
Your laptop
     |
     | docker push
     ↓
Docker Hub
     |
     | docker pull
     ↓
Production server
```

### 2. Private Registry

Instead of Docker Hub, **you create your own server that stores Docker images**.

```text
Your laptop
     |
     | docker push
     ↓
YOUR PRIVATE REGISTRY
     |
     | docker pull
     ↓
Production server
```

That's all a private registry is.

---

### 3. Where does the registry run?

You can run the registry itself as a Docker container:

```text
Host machine
│
├── Docker Engine
│
└── Registry container
      │
      └── stores Docker images
```

The official registry software is available as an image:

```bash
registry:2
```

So:

```bash
docker run -d -p 5000:5000 --name registry registry:2
```

means:

> "Create a container running a Docker Registry server and expose it on port 5000."

Now your machine has a private registry at:

```text
localhost:5000
```

---

### 4. Then the workflow becomes

Tag it for your registry:

```bash
docker build -t localhost:5000/myapp:1.0 .
```

Push:

```bash
docker push localhost:5000/myapp:1.0
```

Now the registry stores:

```text
localhost:5000/myapp:1.0
```

Another machine can then do:

```bash
docker pull <registry-address>/myapp:1.0
```

### The key thing to remember

**Registry = a server that stores Docker images so Docker clients can push and pull them.**

Docker Hub is a registry.

Your company's internal registry can be a private registry.

A registry itself can also run **inside a Docker container**.
