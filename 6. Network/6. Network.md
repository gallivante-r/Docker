### 1. Default Networks Created by Docker

When Docker is installed, it automatically sets up three default networks. You can view them using `docker network ls`:

* **`bridge` (Default)**
* **What it is:** An internal network created automatically by Docker on the host.
* **IP Addressing:** Containers connected to this network get an internal IP address assigned from an internal network pool (typically in the `172.17.x.x` series).
* **Communication:** Containers on this network can talk to each other internally using these private IP addresses.
* **External Access:** To access these containers from outside the Docker host, you must map ports using the `-p` or `--publish` flag (e.g., `-p 8080:80`).


* **`host`**
* **What it is:** Removes network isolation between the container and the Docker host.
* **Port Mapping:** Port mapping is not necessary because the container uses the host's network directly (e.g., if a web app runs on port `80` inside the container, it immediately listens on port `80` of the host).
* **Limitation:** You cannot run multiple instances of a container using the same port on the same host (e.g., two web apps both trying to use port `80`).


* **`none`**
* **What it is:** Complete network isolation.
* **Behavior:** Containers attached to `none` have no access to external networks or other containers. They are completely isolated inside their own network namespace.

### 2. User-Defined Custom Networks

In addition to the three built-in networks, Docker allows you to create custom isolated networks.

* **Creating a Network:**
```bash
docker network create \
  --driver bridge \
  --subnet 182.18.0.0/16 \
  custom-network

```


* **Listing Networks:**
```bash
docker network ls

```


*(Displays the driver, network ID, and network name.)*

---

### 3. Key Concepts & Commands Mentioned

* **Inspecting Networks:**
```bash
docker network inspect <network_name_or_id>

```


* Shows detailed configuration, subnet information, gateway details, and all containers currently attached to that network.


* **Embedded DNS:**
* Containers running on custom user-defined networks can reach each other using their **container names** (hostnames) rather than relying on dynamic IP addresses, thanks to Docker's built-in DNS service.
* **Note :**  On the default bridge network, containers can communicate using their container IP addresses, but not automatically by container name
