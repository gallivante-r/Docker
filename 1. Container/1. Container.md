## 🐳 Containers — Final Cheat Sheet

### 1. Core concept

> **A container packages an application + its libraries + dependencies + filesystem, but shares the host OS's kernel.**

```text
Host Machine
└── Host OS
    └── Linux Kernel  ← shared
        ├── Container A
        │   ├── App
        │   ├── Libraries
        │   └── Dependencies
        └── Container B
            ├── App
            ├── Libraries
            └── Dependencies
```

---

### 2. Host

**Host = machine/OS directly running the container runtime.**

It can be:

* Physical machine/laptop
* VM

The **Linux kernel belongs to the host OS** and is shared by containers.

---

### 3. LXC / LXD / LXCFS

| Technology | Purpose                                                |
| ---------- | ------------------------------------------------------ |
| **LXC**    | Creates/runs Linux containers                          |
| **LXD**    | Manages LXC containers                                 |
| **LXCFS**  | Makes certain system-information views container-aware |

**LXCFS example:**

```text
Host:       32 CPU, 128 GB RAM
Container:   4 CPU,   8 GB RAM

Application asks:
"How much RAM do I have?"

LXCFS → presents a view reflecting the container's 8 GB
```

> **LXCFS doesn't change the container's limits; it makes system-information interfaces reflect those limits.**

---

### 4. Linux kernel & system information

The kernel exposes information through interfaces such as:

```text
/proc → CPU, memory, processes, uptime, load, etc.
/sys  → devices, kernel subsystems, cgroups, etc.
```

Because containers share the host kernel:

```text
Host Linux Kernel
       ↓
   /proc /sys
       ↓
   Container
```

LXCFS can provide **container-aware views** of some of this information.

---

### 5. Docker's stack

Docker normally **doesn't use LXC/LXD**.

```text
docker CLI
    ↓
Docker Engine
    ↓
containerd
    ↓
runc
    ↓
Linux Kernel
```

* **Docker Engine** → overall Docker container management
* **containerd** → container lifecycle management
* **runc** → low-level runtime that creates/runs the container
* **Linux Kernel** → provides isolation/resource mechanisms

---

### 6. OCI

**OCI = Open Container Initiative**

> Defines standards for container **images** and **runtimes**.

```text
OCI
├── Image Specification
└── Runtime Specification
```

`runc` implements the OCI Runtime Specification.

---

## 🧠 Final memory trick

```text
LXC   → Create/Run
LXD   → Manage
LXCFS → Container-aware system information

Docker → Container platform
containerd → Container lifecycle
runc → Actually runs/creates container

OCI → Container standards

Linux Kernel → Underlying kernel shared by containers
```

### Most important interview statement

> **Containers isolate applications using the host Linux kernel. They have their own user-space files, libraries and dependencies, but they do not have their own kernel.**

# Commands

```bash
# To stop and delete the containers:
docker rm -f redis
docker rm -f clickcounter

# Unused stopped containers
# Unused networks
# Dangling images
# Unused build cache
docker system prune

# Delete all Docker images that are not currently used by any container.
docker image prune -a
docker inspect containerId/Name
docker logs containerId/Name
```
